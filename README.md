# IEE-CIS Fraud Detection

კონკურსის აღწერა: კონკურსის მიზანია ისეთი მოდელის ტრენინგი, რომელიც მოცემული ტრანზაქციის მონაცემების საფუძველზე განსაზღვრავს, ტრანზაქცია თაღლითურია თუ არა. მონაცემები წარმოდგენილია ორ ცხრილად: train_transaction.csv და train_identity.csv, რომლებიც გაერთიანებულია TransactionID-ის საშუალებით. სამიზნე ცვლადია isFraud, სადაც 1 ნიშნავს თაღლითურ ტრანზაქციას.

რეპოზიტორიის სტრუქტურა: რეპოზიტორია შედგება ხუთი ცალკეული notebook-ისგან თითოეული მოდელისთვის, ესენია: Logistic Regression, Decision Tree, Random Forest, AdaBoost და XGBoost. საუკეთესო მოდელის Model Registry-დან ჩამოტვირთვა და submission.csv-ის გენერაცია Kaggle-ზე ასატვირთად ხდება model_inference.ipynb-ში. README.md-ში შეძლებთ ნახოთ ჩემს მიერ გამოყენებული მიდგომები და მათი შედეგები.

EDA: მონაცემებზე დაკვირვებით დავაფიქსირე, რომ კლასებს შორის დისბალანსი საკმაოდ მაღალია, მხოლოდ 3.5% შემთხვევაა თაღლითური. TransactionAmt-ისთვის საშუალო 135$, ხოლო საშუალო სტანდარტული გადახრა 239$ აღმოჩნდა, რაც log transformation-ის საჭიროებაზე მიმითითებდა. რაც შეეხება გამოტოვებულ მნიშვნელობებს, ისინი გვხვდებოდა 414 სვეტში, საიდანაც 214 სვეტი 50%-ზე მეტად იყო ცარიელი. აღსანიშნავია V-სვეტების (V257, V246, V244) მაღალი კორელაციაც სამიზნე ცვლადთან.

Cleaning: ეს ეტაპი თითქმის ყველა მოდელისთვის მსგავსია. transaction და identity ცხრილები დავმერჯე TransactionID-ზე, შემდეგ დავდროპე სვეტები, რომლებიც დიდი რაოდენობით missing data-ს შეიცავდნენ. ასევე დავდროპე TransactionDT სვეტი, ვინაიდან მისგან time feature-ები ამოვიღე. AdaBoost-ის notebook-ში დამატებით outlier removal-ც გავაკეთე mean + 3*std მეთოდით, ვინაიდან AdaBoost განსაკუთრებით მგრძნობიარეა ექსტრემალური მნიშვნელობების მიმართ.

Feature Engineering: ამ ნაწილში OHE-ის ნაცვლად გამოვიყენე frequency encoding — კატეგორიული მნიშვნელობები შევცვალე მათი სიხშირით სატრენინგო მონაცემებში, რადგან ეს მიდგომა გაცილებით სწრაფია და tree-based მოდელებისთვის უკეთ მუშაობს. TransactionDT ცვლადიდან გამოვყავი დროითი მახასიათებლები: საათი, დღე, is_night და is_weekend. TransactionAmt-ზე გამოვიყენე log transformation, ასევე დავამატე ცენტის ნაწილი და მრგვალი თანხის ინდიკატორი (flag). email feature-ებიდან შევქმენი ახალი ცვლადები: is_gmail, is_yahoo და same_email (ამ უკანასკნელით ხდება P და R emaildomain-ების შედარება). მოდელისთვის ყველაზე predictive აღმოჩნდა card აგრეგაციები: card1 და card2-ის მიხედვით გამოთვლილი TransactionAmt-ის საშუალო, სტანდარტული გადახრ, სხვაობა და შეფარდება. ეს ცვლადები კარგად ასახავს გადახრას ბარათის ტიპურ აქტივობასა და მიმდინარე ტრანზაქციას შორის. მონაცემთა დამუშავებისას, გამოტოვებული მნიშვნელობები Pipeline-ის შიგნით SimpleImputer-ით შევავსე, ხოლო უშუალოდ XGBoost-ისთვის გამოვიყენე fillna(-999).

Feature Selection: მისთვის გამოვიყენე სამი სხვადასხვა მიდგომა. Variance Filter-ით დავდროპე 2 სვეტი, რომელთა სტანდარტული გადახრა 0.01-ზე ნაკლები იყო. Correlation Filter-ით (threshold > 0.9) კიდევ 100-ზე მეტი სვეტი დავდროპე. მესამე მიდგომა, XGBoost Feature Importance-ი, ყველაზე ეფექტური აღმოჩნდა — სწრაფი XGBoost-ის ტრენინგით feature importance-ები ავიღე და top-150 შევინარჩუნე. საინტერესო იყო ის, რომ XGBoost-ის საბოლოო ვარიანტში correlation filter-ი სულ გამოვრთე, ვინაიდან V-სვეტებს კლავდა, რომლებიც სამიზნე ცვლადთან ყველაზე მეტად კორელირებული feature-ები იყვნენ.

Training: ამ ეტაპზე ხუთი მოდელი გავტესტე. Logistic Regression-ზე C პარამეტრის sweep-მა (0.001-დან 10-მდე) და L1/L2 რეგულარიზაციების შედარებამ აჩვენა, რომ AUC თითქმის არ იცვლება და 0.822-ის ფარგლებში რჩება. ეს ტიპური underfitting-ია, Logistic Regression ვერ ხედავს ამ მონაცემების რთულ, არაწრფივ სტრუქტურას. Decision Tree-ს შემთხვევაში max_depth-ით ექსპერიმენტირება საინტერესო გამოდგა. depth=2-ზე მივიღეთ 0.72 AUC (underfitting). შეუზღუდავ სიღრმეზე (depth=None) კი იწვევს overfitting-ს: Train-ზე 1.0 გვაქვს, Test-ზე კი — 0.77. ოპტიმალური წერტილი depth=10-ზე აღმოჩნდა. Random Forest-მა კარგად გამოაჩინა ensemble model-ების ძალა. თუ ერთი ხე 0.77 AUC-ს იძლეოდა, RF-მა ეს მაჩვენებელი 0.9370-მდე გაზარდა. შედეგები n_estimators=100-დან უკვე სტაბილური ხდება. AdaBoost-ის ტესტირებისას ვნახე, რომ depth=1 (stump) იძლევა 0.8443-ს, ხოლო depth=4-ზე შედეგი 0.8816-მდე იზრდება. აქვე გამოჩნდა, რომ ძალიან დაბალი learning_rate (0.01) ისევ underfitting-ს იწვევს (0.6916). ყველაზე კომპლექსური სამუშაო XGBoost-ზე ჩავატარე. ერთმანეთს შევადარე scale_pos_weight და RandomUnderSampler და პირველმა უკეთესი შედეგი აჩვენა. Early stopping-ის დახმარებით ოპტიმალურ წერტილად 764 ხე განისაზღვრა. Threshold tuning-მა შედეგი საგრძნობლად გააუმჯობესა: ნაგულისხმევი 0.5-ის ნაცვლად, ზღვარი 0.839-ზე დავაყენეთ, რამაც F1 score 0.47-დან 0.66-მდე ასწია.

საბოლოოდ არჩევანი XGBoost-ზე შევაჩერე, რადგან მან საუკეთესო პერფორმანსი აჩვენა. კლასების დისბალანსს scale_pos_weight-ით ვაბალანსებ, early stopping-ით კი თავიდან ვიცილებ overfitting-ს. თვითონ XGBoost-ის ალგორითმი ყველაზე კარგად მოერგო თაღლითობის არაწრფივ პატერნებს. მოდელი შევინახე Model Registry-ში სახელით XGBoost_Fraud_Pipeline_Run2 (ვერსია 2). მას პირდაპირ model_inference.ipynb-ში ვტვირთავ და ვაგენერირებ ფინალურ submission ფაილს.

მოდელების შედარებითმა ანალიზმა აჩვენა მკაფიო პროგრესი მათი სირთულისა და სიზუსტის მიხედვით: ყველაზე დაბალი მაჩვენებელი Logistic Regression-მა დააფიქსირა (0.8204 AUC), რაც მიუთითებს იმაზე, რომ ხაზოვანი მოდელები ვერ აღიქვამენ ამ მონაცემების სპეციფიკას, შედარებით უკეთესი შედეგი აჩვენა Decision Tree-მ (0.8789 AUC), თუმცა მან ვერ მიაღწია ensemble model-ების დონეს, რომელთა გამოყენებამაც სიზუსტე მნიშვნელოვნად გაზარდა, კერძოდ, AdaBoost-მა 0.9020-ს მიაღწია, Random Forest-მა 0.9370-იანი მაჩვენებელი აჩვენა, ხოლო საუკეთესო პერფორმანსი XGBoost-მა დააფიქსირა, რომლის Test AUC-მაც 0.9585 შეადგინა. საბოლოო მოდელის ვალიდაცია მოხდა Kaggle-ზე, სადაც Public Score-მა 0.9038 შეადგინა, რაც ადასტურებს, რომ მოდელი სტაბილურია, წარმატებით ახდენს თაღლითური ტრანზაქციების იდენტიფიცირებას რეალურ მონაცემებზე და კარგად უმკლავდება მონაცემებში არსებულ არაწრფივ კანონზომიერებებს.
